## 旧版问题：代码事实与解释

核查 `../midi_driven_hand_posture_and_contact_refinement_r1/01_coordinate.py`、`HAND_POSTURE_COORDINATION_R1.json`、`KEY_CONTACT_R1.json`。

1. **自然姿态目标没有真人标定。** `qrest`、`natural` 是 RSSF 的固定增量，`drive` 是激活量的加权组合。左手闲置指刚硬可能来自这些低维目标；这是基于实现与画面的因果假说，不是受控消融结论。
2. **已有 shared root，但目标仍偏单帧。** 每个时间点用前一解预测，求解当下活跃/准备/释放 pad；掌部正则拉向初始化 `base`。缺少跨下一音的整体手型、掌部承载和重新布置计划。不能把问题错误归为“旧版五指各自没有共同手掌”。
3. **平滑不等于自然。** 已有硬速度/加速度边界，并已消除原始跳变；曲线仍可以连续而机械。旧 active 姿态回到 `homeq`，非主动姿态回到少数相同固定弯曲值，缺少任务相关的指间差异。
4. **净空代理弱于最终网格。** 求解用 RSSF 中 12 个低位掌部点及 idle pads；真实蒙皮形状和各键体边界并未作为完整几何约束进入规划。最终网格筛查仍出现 L 129/409、R 10/409 个掌部碰撞观察。区域是粗分段，含近端拇指，需保留该局限。
5. **接触目标只是单点路径。** 固定每指入键深度、准备抬高 22 mm/释放 27 mm 及状态时长来自工程策略，不是已验证的示范轨迹。R F# 的后移、高差及触点朝向需要共同掌姿配合。
6. **身体上下文不足。** root 有三维自由度，但没有完整前臂/肘。当前只能判断局部可见可信度；不能输出人体工学合格结论。
