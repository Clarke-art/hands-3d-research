## 0. 结论摘要

用于生成 **Canonical Right Hand Master** 的初始手姿态定义为：

> ## `CANONICAL_HAND_POSE`
> ### **Relaxed Splayed Semi-Flexed Hand（RSSF）**— 自然放松 · 五指扇形张开 · 半屈曲手型
>
> **一句话**：一只**完全放松的右手**，保持"手臂自然下垂时手的天然形状"（手指轻曲、掌指关节成拱），
> 再把五指**主动张开成扇形**（相邻指间夹角约 10–15°），
> 手腕置于**中立位**，掌背朝 **+Y**、掌心朝 **−Y**，
> **整体悬空**——不接触桌面、琴键或任何实体支撑面。
>
> ⚠ **"水平参考面"是虚拟坐标参考，不是实体桌面。** 采集时手必须悬空，
> 不得让掌部、手指、指尖接触实体平面，不得因支撑而压平掌弓。见 §2.2。

**为什么不是最终钢琴手型**：钢琴手型是"功能姿态"，五指并拢一指一键、掌指关节屈曲较大，在多视角轮廓重建中会造成**指间遮挡与指缝粘连**，且接近关节活动范围一端，作为绑定中性姿态会导致后续动画范围不对称、蒙皮在极端姿态失真。

**为什么不是完全僵硬的医学 T Pose**：五指伸直并拢会使**关节轮廓消失**（Retopo 时找不到关节环线位置）、**指缝粘连**、**拇指与掌共面导致"猿手"**，且伸直到 0° 是关节极限，蒙皮易在关节处塌陷。

→ RSSF 是刻意选取的**中间态**：既保证五指边界清晰、关节可辨识，又让所有关节都处于**活动范围中段**，为后续双向动画留出最大余量。

**手指骨节数（硬性事实）**：
- 拇指（1 指）：**2 节**指骨（近节 + 远节）→ 关节链 CMC → MCP → IP（3 个关节）
- 食指 / 中指 / 无名指 / 小指（2–5 指）：**3 节**指骨（近节 + 中节 + 远节）→ 关节链 MCP → PIP → DIP（3 个关节）
- **每只手合计 16 个关节**（1 腕 + 5 指 × 3）。此数与图形学界通用手部参数模型 MANO 的 16 关节骨架一致（见 §7 依据）。

### 2.2 手掌朝向、"水平参考面"的澄清与悬空要求

#### 2.2.1 手掌朝向规定

**规定**：掌背朝 **+Y**、掌心朝 **−Y**。这是一个**姿态朝向定义**，**不是**"把手放在桌面上"的动作指令。

#### 2.2.2 ⚠ "水平参考面" = VIRTUAL COORDINATE REFERENCE（R1.1 澄清）

R1 版中"掌背朝上、掌心朝下平放于水平参考面"的表述**容易被误解为手实际放在桌面上**。此处明确更正：

| | 说明 |
| --- | --- |
| **"水平参考面"是什么** | **仅为虚拟坐标参考（VIRTUAL COORDINATE REFERENCE）**。它是 Asset Frame 中用于描述"掌心朝向 −Y"这一朝向语义的抽象平面，**不是实体桌面，不是拍摄台面，不是任何物理支撑面**。 |
| **采集时手的状态** | **必须悬空**。掌部、手指、指尖**一律不得**接触实体平面。 |
| **禁止的压平** | 不得因任何支撑方式压平**掌心横弓与纵弓**（`G-05`）。掌弓一旦被压平，掌心结构丢失，E-08「手掌贴键」对比将失去正常对照。 |
| **允许的支撑** | 只允许固定**前臂末端**（悬臂式固定），使手在自重下自然保持 `CANONICAL_HAND_POSE`。支撑物不得进入最终手部主体区域。 |
| **为什么必须悬空** | ① 实体接触面会遮挡掌心/指腹，直接破坏 PALMAR 视角；② 接触面会压平掌弓；③ 接触边界会在多视角重建中产生错误的几何截断。 |

#### 2.2.3 朝向选择的理由

| 考量 | 说明 |
| --- | --- |
| **轮廓信息最大化** | 此朝向下，掌背侧 + 五指背侧在同一视图内全部可见，相互遮挡最小 |
| **关节可辨识** | 掌指关节（MCP）凸起、指间关节轮廓、指甲均在掌背侧最清晰 |
| **教学主视角一致** | 学生观察钢琴手型的主要视角就是**斜前俯视手背**；母版与教学主视角同源，可减少后续渲染时的视角偏差 |
| **避免"握拳式自遮挡"** | 若采用掌心朝上放松姿态，手指会自然向掌心卷曲，造成指间严重自遮挡——这是手部 3D 重建最常见的失败模式 |
| **指尖轮廓可从侧视角完整看到** | MCP/PIP/DIP 半屈曲 + 手悬空，指尖下方无任何遮挡物，从 RADIAL / ULNAR 侧视角可完整看到指尖轮廓 |

### 2.3 拇指——最容易失败的部分

拇指是手部 3D 生成**失败率最高**的部位。规定：

1. **必须离开掌平面**（CMC 屈曲 20–30°），不得与四指共面。
2. **必须显著旋前**：拇指指甲面与其余四指指甲面成约 45–70° 夹角。这是解剖学事实（拇指仅 2 节指骨、CMC 为鞍状关节），也是 AI 生成"猿手"（thumb 方向与其余四指趋同，看起来像第五根手指）的**唯一有效判别特征**。
3. **虎口（第一指蹼）必须张开 35–45°**，不得夹紧（教学依据：B-13 / 中文"虎口夹紧"列为错误）。
4. **拇指长度最短**，其指尖不应超过食指 PIP 关节附近。

> **验收硬指标**：从掌背视角（DORSAL）看，拇指的中轴延长线与食指中轴延长线之间的夹角应明显可测；若拇指看起来"像第五根手指"，判定失败，需重新生成。

### 2.4 为什么这个姿态适合作为后续动画母体

| # | 理由 | 说明 |
| --- | --- | --- |
| **R-1** | **五指边界清晰、指间不粘连** | 10–15° 扇形张开保证相邻指之间在**任何视角**下都有可见间隙，避免多视角重建时指缝被"缝合"——这是手部 3D 生成的头号失败模式 |
| **R-2** | **关节结构容易识别** | MCP 20–30° / PIP 25–35° / DIP 10–20° 的半屈曲使三个关节在轮廓上都产生**明显的折角**，Retopo 时可直接沿折角定位关节环线 |
| **R-3** | **后续容易 Retopo** | 关节折角 + 指间间隙 = 明确的拓扑引导；且姿态对称、无极端扭曲，四边形布线的极点（pole）位置容易规划 |
| **R-4** | **容易绑定骨骼** | 姿态接近绑定中性姿态，骨骼可直接按解剖位置放置；关节处于**活动范围中段**，蒙皮权重的中性分配最均匀，向屈曲与伸展两个方向变形都自然 |
| **R-5** | **手指具有足够活动范围** | 所有关节都在中段，既留出了屈曲到握拳/钢琴手型的余量，也留出了伸展到平直的余量。**这是不用钢琴手型作母版的核心原因** |
| **R-6** | **不是僵硬的医学 T Pose** | 完全伸直并拢会（a）让关节轮廓消失（R-2 失效）；（b）指缝粘连（R-1 失效）；（c）拇指与掌共面 → 猿手；（d）0° 伸直即关节极限，蒙皮在关节处塌陷。RSSF 全部规避 |
| **R-7** | **与 RELAXED 姿态高度接近** | 教学规范要求的 RELAXED（"自然下垂手形"）与 RSSF 只差"五指是否张开"。这意味着 RELAXED 姿态几乎不需要额外修正，且张开是可逆的 |
| **R-8** | **不引入外部遮挡物** | 不接触琴键，符合多视角生成的"不得被其他物体遮挡"要求 |
| **R-9** | **左右手镜像友好** | 姿态关于掌平面的左右镜像无歧义，镜像后法线与权重翻转可控 |

## 3. 关键参数的推导依据

### 3.1 手指张开角 10–15° 的推导

- **下限**：必须大于"自然放松"时的指间间隙。自然放松时相邻指尖间隙很小，从侧视角（RADIAL / ULNAR）看五指会相互遮挡轮廓 → 重建时指缝粘连。
- **上限**：张开过大（>20°）会拉伸指蹼（web space）皮肤、改变指蹼几何，使生成的指蹼偏厚，且使手指不能自然并拢到"一指一键"的教学姿态（教学依据 B-07）。
- **折中**：10–15° 是既能保证任意视角下指间可见间隙、又不过度拉伸指蹼的区间。

> ## ✅ `HR-06b` = **`APPROVED_AS_TECHNICAL_RANGE`**（R1.2 裁定）
>
> **采用：相邻指间张开约 10–15°。**
>
> **🚫 必须明确这不是什么**：
> **这不是钢琴 `STANDARD_HAND` 的教学角度。**
> 它只是 **`CANONICAL_HAND_POSE` / RSSF 母版生成 / 工程 re-pose / Rig neutral pose** 所使用的**技术范围**。
> （R1.3 注：Hunyuan3D 多视角重建只是应用该范围的**分支场景之一**，不再是唯一场景。）
>
> **🎯 技术目的**：
> - 保证指间存在**可见间隙**；
> - 降低**指缝粘连**；
> - 降低**侧视角遮挡**；
> - 又**不过度拉伸指蹼**。
>
> **🚫 不得锁成单一数值。** 不要要求"所有手必须正好 12°"之类**假精确**。
>
> **✅ 正确含义**：大致处于 10–15° 技术范围，
> **以视觉上五指分离清晰、指蹼不过度拉伸为实际判据**。
>
> **→ `HR-06b` 不再阻塞 Stage 1。**

### 3.2 MCP 20–30° / PIP 25–35° / DIP 10–20° 的推导

- 这三个数值整体对应"**手自然放松、手指轻曲**"的形状（Baylor L1 的 "fingers are gently curved"，WPTA L2 的 "extending downward in a gentle curve from the main knuckle"）。
- **MCP 与 PIP 取较大值**：让掌指关节保持拱起（教学 B-02 "powerhouse arch"），并使关节折角足够明显（R-2）。
- **DIP 取较小值**：避免指尖过度卷向掌心造成自遮挡（R-1 / §2.2）；同时保持 DIP 关节轻微可见。
- **均远离 0° 与极限**：保证 R-5（双向活动余量）与 R-4（蒙皮中性）。

> ## ✅ `HR-06c` = **`APPROVED_AS_TECHNICAL_RANGE`**（R1.2 裁定）
>
> **采用：MCP 约 20–30° / PIP 约 25–35° / DIP 约 10–20°。**
>
> **📌 这些数值只用于**：
> - `CANONICAL_HAND_POSE` / **RSSF**
> - **RSSF 母版生成 / 工程 re-pose**（R1.3：Route C 下由 Stage 4 临时骨架 re-pose 落实）
> - **Hunyuan3D 母版生成**（⚠ 仅 fallback 分支）
> - **Rig neutral pose**
>
> **🚫 它们是技术范围，不是 `STANDARD_HAND`（标准钢琴手型）的教学参数。**
>
> **🚫 不得用它们**：
> - 定义**标准钢琴手型**；
> - 定义**学生正确触键姿势**；
> - 代替 **`HR-01` / `HR-02` / `REFERENCE_GAP-04`**。
>
> **`STANDARD_HAND` 的具体角度，仍然必须由后续教学依据与人工裁定决定。**
>
> **→ `HR-06c` 不再阻塞 Stage 1。**

### 3.3 关于 16 关节骨架

母版姿态的可动关节为 **16 个/手**（1 腕 + 5 指 × 3），与图形学界通用手部参数模型 **MANO** 的骨架一致（θ ∈ R⁴⁸ = 16 joints × 3 DoF）。选择 16 关节而非更细分的骨架，理由：
- 覆盖所有教学所需变形（握拳、拱形、单指触键、塌陷对比）；
- 骨骼数量少，Web 端 AnimationMixer 与 GPU 蒙皮开销低；
- 与业界标准对齐，便于未来（如需）用动捕或参数化模型辅助。

> **正确原则（R1.2 最终形式）**：
>
> ```
>        HAND   = FIXED   （手保持 CANONICAL_HAND_POSE，一动不动）
>        LIGHT  = FIXED   （灯位/方向/强度/色温/柔光环境全程不变）
>        CAMERA = MOVES   （相机围绕手移动到 8 个机位）
>
>        而不是：
>        CAMERA = FIXED
>        HAND   = FLIPPED            ❌ 已废弃
>
>        也不是：
>        LIGHT  = FOLLOWS CAMERA     ❌ R1.2 废弃（光源随相机移动）
> ```
>

## 5. 生成范围：`手 + 短前臂`（`HR-06` = APPROVED，R1.1 定稿）

### 5.1 裁定结果

> ## ✅ `HR-06` = **APPROVED**
> **生成范围确定为：手 + 短前臂。**

R1 版中的三个候选方案（A 仅手 / B 手+短前臂 / C 手+完整前臂）中，**采纳 B**。
方案 A（仅手）被排除：会使 E-05「手腕过高」、E-06「手腕过低」两项 3D 对比**无法制作**。
方案 C（完整前臂）被排除：对基础手型教学无额外价值，只增加面数与 Web 端负担。

### 5.2 ⚠ 删除"固定 3–5 cm"硬性规则（R1.1）

R1 版曾写"手 + 短前臂（约 3–5 cm）"。**该固定厘米数规则已删除，不再作为硬性要求。**

**新的原则性规定**：

| # | 原则 |
| --- | --- |
| **FR-01** | 短前臂长度**不预设固定数值**。"3–5 cm"降为**参考量级**，非硬性约束。 |
| **FR-02** | 短前臂必须**足够长**，以完整表达 **「前臂 — 手腕 — 手掌」的方向关系与连续关系**。判据：观察者应能从 RADIAL / ULNAR 侧视角清楚读出前臂轴线、腕关节、掌部三者构成的一条柔和直线（教学依据 B-12、WPTA(L2) "a straight line from the wrist to the knuckles"）。 |
| **FR-03** | 必须能支持以下三项 3D 教学比较的表达：<br>① **手腕过高**（E-05）<br>② **手腕过低**（E-06）<br>③ **腕部中立**（B-08 / 标准手型） |
| **FR-04** | **不得包含无教学价值的完整前臂**。截断点应在"足以表达上述关系"之后的**最近处**，不得延伸至肘部。 |
| **FR-05** | **最终裁切长度在首个 Geometry Candidate 上根据视觉效果确定**（Stage 3 Geometry Review 阶段，由人工在模型上目视裁定并记入 `GEOMETRY_REVIEW_REPORT.md`）。 |

### 5.3 为什么这样定

- 前臂段存在的**唯一理由**是表达"前臂—手腕—手掌"的方向与连续关系，从而支撑腕部三态（过高 / 中立 / 过低）的教学比较。离开这个目的，多出来的前臂就是纯成本（面数、遮挡、Web 负担）。
- 因此长度应由**教学可视效果**反推，而不是由任意厘米数规定。不同成人手的实际尺寸不同，固定厘米数没有意义。

> **下游影响**：参考图构图（PROXIMAL 视角需拍到前臂断端）、面数预算、Three.js 中双手与键盘的遮挡处理。
