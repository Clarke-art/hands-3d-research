### 1.4 `HR-07` 重写 = **RESOLVED**（采集原则）

#### ❌ 先删除错误前提

R1 版把 DORSAL 与 PALMAR 的采集理解为"**翻转真人手 180° 后分别拍摄**"，并由此推导出一系列补救方案（物理夹具 / 镜面 / 翻模 / CC0 基准图）。

**这个前提是错的。** 它隐含假设了 **CAMERA = FIXED**（相机不动）。去掉这个假设后，"掌心视图"根本不需要翻手——**把相机移到手的下方去拍就可以了。**

#### ✅ 正确原则

```
        ✅ 正确                          ❌ 错误（已废弃）

        HAND   = FIXED                   CAMERA = FIXED
        CAMERA = MOVES                   HAND   = FLIPPED

        手保持 CANONICAL_HAND_POSE       手被翻转 180° 重拍
        一动不动；                        → 关节角度漂移
        相机围绕手移动到 8 个机位          → 张开角不一致
        → 姿态天然一致                    → 掌弓被压平
```

**DORSAL 与 PALMAR 不再是"一对需要翻手才能凑齐的矛盾视角"，而只是同一只不动的手从 +Y 侧与 −Y 侧各拍一张。**

#### 首选采集路线（A–G，写入多视角规范 §5.2）

| 步骤 | 规定 |
| --- | --- |
| **A** | 固定**前臂末端**，使手**悬空**保持 `CANONICAL_HAND_POSE` |
| **B** | 支撑物**不得进入最终手部主体区域**（腕以远部分） |
| **C** | **相机围绕固定手移动**到 8 个机位 |
| **D** | 获取 DORSAL / PALMAR / RADIAL / ULNAR / DISTAL / PROXIMAL / 两个斜视图 |
| **E** | 全程**同一只右手、同一姿态**；手不得被翻转、转动或重新摆放 |
| **F** | **多相机同步采集优先**（条件允许时） |
| **G** | **单相机快速环绕采集**作为可行方案（须做 `DORSAL_PRE` / `DORSAL_POST` 漂移校验） |

#### 配套的两条新硬约束

| ID | 约束 | 理由 |
| --- | --- | --- |
| **MV-01** | 相机—手距离在每个机位保持一致（相机在以手为中心的**球面**上移动，不是前后推拉） | 距离变化会破坏透视一致性 |
| **MV-02** | 光照需随相机移动重新布置，或采用环绕式柔光 | 相机移动后固定光源会导致各视角光照不一致 |

#### 状态重估：是否仍是 Blocking？

| 项 | 结论 |
| --- | --- |
| **R1 状态** | `HUMAN_REVIEW_REQUIRED` / **Blocking**（阻塞参考图采集） |
| **R1.1 状态** | ✅ **RESOLVED** |
| **判定理由** | R1 中真正阻塞的，是"**如何在不破坏姿态一致性的前提下获得相对视角（尤其 PALMAR）**"这一**规范层面的方法学未决问题**。R1.1 已用 `HAND = FIXED / CAMERA = MOVES` **在规范层面解决了该问题**——方法学已定、首选路线（A–G）已给，不再存在需要人工在若干互斥方案间做选择的未决点。 |
| **残留事项（非阻塞）** | 悬臂固定装置制作、相机阵列或环绕拍摄的执行、模特授权与预算 → 属 **Stage 1 执行准备事项**，不阻塞规范审核 |
| **残留风险** | **RK-14**：相机移动破坏光照一致性。已由 `MV-02` 约束 + 优先多相机同步缓解 |

> **净效果**：GATE 1 的阻塞项由 **7 项降至 1 项**（仅剩 `REFERENCE_GAP-02`）。

### 1.5 "水平参考面"澄清 = **VIRTUAL COORDINATE REFERENCE**

R1 版"掌背朝上、掌心朝下**平放于水平参考面**"容易被误解为手实际放在桌面上。R1.1 明确更正：

| | 说明 |
| --- | --- |
| **"水平参考面"是什么** | **仅为虚拟坐标参考**。它是 Asset Frame 中用于描述"掌心朝向 −Y"这一**朝向语义**的抽象平面，**不是实体桌面、不是拍摄台面、不是任何物理支撑面** |
| **采集时手的状态** | **必须悬空**。掌部、手指、指尖**一律不得**接触实体平面 |
| **禁止的压平** | 不得因任何支撑方式压平**掌心横弓与纵弓**（`G-05`）。掌弓一旦被压平，掌心结构丢失，E-08「手掌贴键」对比将失去正常对照 |
| **允许的支撑** | 只允许固定**前臂末端**（悬臂式），使手在自重下自然保持姿态 |
| **为什么必须悬空** | ① 实体接触面会遮挡掌心/指腹，直接破坏 PALMAR 视角；② 接触面压平掌弓；③ 接触边界会在多视角重建中产生错误的几何截断 |

**写入位置**：`CANONICAL_HAND_POSE_SPEC_R1.md` §0 摘要、§2.1 姿态总表、§2.2（整节重写）；`MULTIVIEW_REFERENCE_PACK_SPEC_R1.md` §2.1、§2.4、§7 检查清单。

### 1.6 `DIP_ERROR_DEMO_CONFLICT` = **RESOLVED**（双模式）

#### R1 中存在的逻辑冲突

| 条款 | 要求 |
| --- | --- |
| **R-04** | DIP **禁止**负向 hyperextension（正常教学的必要约束，`C-SH-05`） |
| **R-05** | DIP **必须能塌陷 / 反折**以演示错误手型 E-04「折指」（`C-ERR-02`） |

若不做区分：要么互相抵消（错误示范做不出来），要么导致学生在自由交互中把手指随意反折（教学上不可接受）。

#### 解法：`NORMAL_MODE` / `ERROR_DEMO_MODE`

同一个 mesh、同一套 Rig，**通过模式切换区分用途**。模式是**运行时状态**，不是两套资产。

| | **`NORMAL_MODE`**（默认） | **`ERROR_DEMO_MODE`** |
| --- | --- | --- |
| **用途** | 正常教学：标准手型、单指触键、自由交互观察 | 错误手型教学：演示 E-04「折指」等 |
| **DIP joint limit** | ✅ **开启**，禁止负向 hyperextension | ⚠ **受控放宽**，允许 `ERR_COLLAPSED_DIP` |
| **谁可进入** | 学生（默认状态） | **仅由教学流程触发**，学生不可自由进入 |
| **学生自由度** | 自由旋转/缩放/点击手指 | 🚫 **禁止学生在普通自由交互状态下把 DIP 随意反折** |
| **退出** | — | 退出错误示范后**必须回到 `NORMAL_MODE`** |

#### `ERR_COLLAPSED_DIP` 的三种实现路径

| 路径 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **P-1 专门 Pose** ⭐ | 预置烘焙好的 `ERR_COLLAPSED_DIP` 静态 Pose | 最简单；无需运行时改 limit；蒙皮可预先验证；Web 性能最好；**架构上不可能让学生自由反折 DIP** | 只能展示一个预设程度的塌陷 |
| **P-2 受控临时 override** | 进入模式时临时放宽 DIP limit，退出时恢复 | 可动态调节塌陷程度 | 需运行时状态管理；须保证退出时必定恢复 |
| **P-3 corrective deformation** | 用 corrective blendshape 直接表现塌陷几何 | 几何表现最可控 | 需额外形变制作；资产复杂度上升 |

> **推荐 P-1**，理由：教学上只需演示"这个错误长什么样"，一个预设程度足够；且 P-1 不触碰 `NORMAL_MODE` 的 limit，**从架构上杜绝了学生自由反折 DIP 的可能**，是最安全的方案。
> **⚠ 最终选择由人工在 Stage 8 前裁定（新增 `HR-13`）。**

#### 硬性约束（DM-01 ~ DM-06）

| ID | 约束 |
| --- | --- |
| **DM-01** | 🚫 **禁止学生在普通自由交互状态下把 DIP 随意反折** |
| **DM-02** | `ERROR_DEMO_MODE` **只能由教学流程触发**，不得由学生自由拖拽/交互进入 |
| **DM-03** | 退出错误示范后**必须回到 `NORMAL_MODE`**，DIP 恢复正向姿态 |
| **DM-04** | 错误示范必须有**明确的 UI 标识**（标注"错误示范"且可与标准手型对比），避免学生误学 |
| **DM-05** | `ERROR_DEMO_MODE` 下 DIP 反折程度须由**教学方确认**（新增 `HR-14`） |
| **DM-06** | 两模式共享**同一个 mesh 与同一套 Rig**（`C-ERR-01`），不得为错误示范另建模型 |
