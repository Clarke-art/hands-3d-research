## 2. 生成参数（固定，不得逐次变动）

> ## 🔑 单一变量原则
> **本合同绑定的具体接口：腾讯云混元生3D专业版 `SubmitHunyuanTo3DProJob`（Version 2023-09-01，`Model = 3.1`）。**
> **该接口当前不暴露 Seed 参数，不存在"固定/改变随机种子"这一操作。**
> 因此第 1 轮 4 个 Candidate = **相同输入 + 相同参数 + 独立重复请求**；
> 允许变化的只有"独立重复请求次数"这一个变量。
> **任何其他参数的变动都必须记录为"另一次实验"，不得混在同一批次的比较中。**
> 若未来改用另一个明确支持 Seed 的腾讯接口，必须**另起实验合同**，不得与当前批次混合。

| 参数 | 规定值 | 理由 |
| --- | --- | --- |
| `GenerateType` | **`Geometry`** | 只取白模，`Geometry first`；排除纹理对几何判断的干扰 |
| `EnablePBR` | **`false`** | `Geometry` 模式下本参数不生效，显式关闭 |
| `FaceCount` | **`100000`** | **`PROJECT TEST VALUE`**（不是接口最低值）。官方范围为 **3000–1500000**（默认 500000）；取 100000 与冻结流水线 Stage 2 的首轮目标区间（80k–150k）一致，保证实验结论可迁移 |
| `MultiViewImages` | **不使用** | 见 §1 |
| `Prompt` | **不使用** | 纯单图；不引入文本先验 |
| 接口版本 | **`HY-3D-3.1`**（Action = `SubmitHunyuanTo3DProJob`，Version 2023-09-01） | 与冻结基线一致 |
| 输出格式 | OBJ 或 GLB（白模） | 便于后续在 Blender 中直接检查 |
| 迭代次数 | **前后共 ≤2 轮**（详见 §5） | 防止无上限试错 |

> ⚠ **不要使用 `LowPoly`**（Model 3.1 下不可用；且智能减面会破坏关节环线）。
> ⚠ **不要使用 `Sketch`**——`PROHIBIT_SKETCH_FOR_THIS_EXPERIMENT`：官方参数枚举仍列有 `Sketch`，**本合同不声称"3.1 已移除 Sketch"**；本合同禁止使用它的原因是**它不符合本轮单图 Geometry-only 实验设计**（且会丢失解剖依据）。
> ⚠ **不要为了"好看"而调高 FaceCount**——面数不是本实验的变量。

## 4. Geometry Review Checklist（强制，逐条判定）

> ## 🔒 只允许三种结论：`PASS` / `CONDITIONAL_PASS` / `FAIL`
> **没有 `N/A`、没有"待定"、没有"基本可以"。**
>
> **"无法验证"的处理规则**：
> 若某项在当前证据下**无法验证**，**必须先判 `CONDITIONAL_PASS`**，并**强制绑定**必须补充的证据项与补证窗口；
> 若在补证窗口内**仍无法补齐证据**，该项**自动改判 `FAIL`**。
> （即：**未经证实 = 不允许通过**。这是本合同最重要的一条纪律。）

### 4.1 判定项

| ID | 判定项 | 检查方法（在哪个视角看） | `PASS` 判据 | `FAIL` 判据 | 通过档位 |
| --- | --- | --- | --- | --- | --- |
| **G1** | **五指完整** | 全部 8 渲染图 + 拓扑视图 | 恰好 1 拇指 + 4 指 = 5 指；无多指、无少指 | 出现 4 指 / 6 指 / 指头融合 | 单值 |
| **G2** | **解剖学右手** | DORSAL + RADIAL + PALMAR | 拇指位于**桡侧**；掌侧与背侧结构类型正确（指甲在背侧、掌纹在掌侧） | 生成出左手；或掌/背类型错位 | 单值 |
| **G3** | **拇指不是"第五根手指"** | RADIAL（必需）+ PALMAR + DORSAL | ① 拇指**仅 2 节**指骨；② CMC 根部位于**腕附近**，不与四指根部齐平；③ **拇指指甲面与四指指甲面明显不共面**（约 45–70°）；④ 虎口（第一指蹼）张开可辨 | 拇指与四指共面（**猿手**）；拇指呈 3 节；拇指根部从掌中部伸出 | **单值（核心项）** |

| **G7** | **掌弓存在** | ULNAR / RADIAL 侧轮廓 + PALMAR | 侧视可见掌骨拱顶轮廓；MCP 关节有可见凸起 | 掌部呈平面板；MCP 无拱顶 | 单值 |
| **G8** | **指尖正常** | DISTAL + DORSAL + 侧视 | 指尖为**圆润锥状末端**，有明确最前端触键点；五指指尖形状一致 | 平切 / 塌陷 / 尖刺 / 指尖被削平 | 单值 |
| **G9** | **指甲不过度** | DORSAL | 指甲为**浅浅的甲面**（轻微隆起 + 边界），形状规整、修剪整齐 | 指甲厚重夸张；指甲缺失导致指尖端面无法定位；指甲被生成在错误侧 | 单值 |

## 5. 迭代与停止规则（防止无上限试错）

### 5.1 第 2 轮的触发条件（**必须同时满足**）

| # | 条件 |
| --- | --- |
| 1 | 第 1 轮 4 个 Candidate **全部为 `FAIL`**；且 |
| 2 | 失败原因**集中在同一个可描述的系统性缺陷**上（例如"全部指缝粘连"或"全部掌心为镜像板"）；且 |
| 3 | 该缺陷**不属于**下列"结构性不可救"类别 |

### 5.2 🚫 结构性不可救（出现即整批结案，不再迭代）

| 缺陷 | 为什么不可救 |
| --- | --- |
| 生成的**手别错误**（左手） | 输入明确是右手；这属于模型侧别理解的系统性错误 |
| **五指数量**错误（多指/少指） | 占比最高的 AI 解剖失败，靠独立重复请求碰运气属于纯运气 |
| **掌心为背面的镜像/模糊复制**（`G5` `FAIL`） | 这是**输入信息缺失**导致的必然结果，**换 seed 不会改变"输入里没有掌心"这个事实** |
| 拇指呈**猿手**且四个 Candidate 一致（`G3` `FAIL`） | 同上：`A02` 中拇指只有桡侧可见，模型缺少判定拇指旋前的视觉证据 |

> 🔑 **判据的核心逻辑**：
> **凡是"因为输入里没有这个信息"而失败的项目，迭代是无意义的**——它只会消耗预算而不改变结论。
> 这正是本合同要与"无限重试"划清界限的地方。

### 5.3 硬性停止

| # | 停止条件 |
| --- | --- |
| S‑1 | Candidate 总数达到 **8** → 停止 |
| S‑2 | 出现 §5.2 中任一结构性缺陷 → **立即停止** |
| S‑3 | 已获得 ≥1 个 `PASS` → 停止（无需跑满） |
| S‑4 | 触发 §6 中任何被禁止的操作意图 → 停止并上报 |

## 6. 🚫 明文禁止（本节是本合同的关键约束）

| # | 禁止项 | 理由 |
| --- | --- | --- |
| **P‑1** | 🚫 **禁止把 Candidate 自己渲染的 8 张图（或任意数量自渲染图）作为 `MultiViewImages` 回炉重建** | 自渲染图不包含关于掌心的任何新观测；多视角重建器会把**几何自洽的错误**当作**高置信度证据**固化下来，结果只会是"错误 + 更光滑"。见选路文档 §8.3 |
| **P‑2** | 🚫 **禁止使用 Stage 1A 的任何派生图**（D01 / P01 / R01 / U01）作为输入 | 已判 `FAIL`，且 `2D_IMAGEGEN_MULTIVIEW_ROUTE = REJECTED_BASELINE` |
| **P‑3** | 🚫 **禁止为了通过 G5 而手工"补"一个掌心** | 本实验的目的是**测量**，不是**改进**。手工补掌心的结果不能用来回答"AI 能恢复到什么程度" |
| **P‑4** | 🚫 **禁止在本实验中生成左手** | `LR-01` |
| **P‑5** | 🚫 **禁止在本实验中做 Retopo / Rig / 权重 / 动画** | 本轮职责边界；这些属于 Stage 4 / 5，且**必须等实验结果经人工裁定后**才启动 |
