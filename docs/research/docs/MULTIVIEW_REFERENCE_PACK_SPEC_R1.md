## 0. 摘要

本文档规定为腾讯混元 3D 多视角生成准备参考图（Reference Pack）的**视角清单、一致性要求、拍摄/采集技术参数、接口参数映射、上机前检查清单**，并**如实登记当前存在的资料缺口**（`REFERENCE_GAP`）。

**核心原则（用户明确要求，本项目严格遵守）**：

> ## 🚫 如果找不到完全一致的一组多视角真人手参考，就如实记录缺口，**绝不把不同来源、不同人、不同姿态的手拼凑伪装成同一只手**。

拼凑不同手的多视角图会导致生成出**几何自相矛盾**的模型（例如指长不匹配、掌宽冲突、拇指比例错误），且这种缺陷往往在 Rig 与蒙皮阶段才暴露，返工成本极高。宁可先停下补齐缺口。

## 2. 一致性要求（硬性）

### 2.1 同一只手（最高优先级）+ 🔑 HAND FIXED / CAMERA MOVES

| 要求 | 说明 |
| --- | --- |
| **🔑 根本原则（R1.1）** | **HAND = FIXED，CAMERA = MOVES。** 手在整个采集过程中保持 `CANONICAL_HAND_POSE` **一动不动**；通过移动相机到不同机位获得 8 个视角。**严禁**为获得某一视角而翻转、转动或重新摆放手。 |
| **同一只手** | 8 个视角必须是**同一只手、同一次拍摄会话**内完成 |
| **同一姿态** | 所有视角必须是**同一个 `CANONICAL_HAND_POSE`**，各关节角度、张开角完全一致 |
| **相同张开状态** | 相邻指间夹角在所有视角下均为 10–15°，不得有的视角张开大、有的小 |
| **同一手势语义** | 不得混入左手、不得混入他人之手 |
| **不得按视角换手** | 严禁为"某个角度更好看"而换另一只手、翻转手或部分手指 |
| **🚫 已废弃的错误做法** | ~~"翻转真人手 180° 以分别获得掌背视图与掌心视图"~~ —— 该前提已在 R1.1 删除，见 §5 |

> **为什么这条是根本原则**：一旦手被翻转或重新摆放，各关节角度、张开角、掌弓形态必然发生漂移（重力与放松程度改变），
> 8 张图就不再是同一姿态，多视角重建会得到**几何自相矛盾**的模型。
> `HAND = FIXED` 从物理上消除了这一风险源——这是 R1.1 相比 R1 最实质的改进。

### 2.2 透视与成像一致性

| 要求 | 规定值 | 理由 |
| --- | --- | --- |
| **透视差异不能过大** | 全部视角使用**同一焦距**，相机—手距离保持一致 | 焦距/距离变化会改变透视比例，使多视角重建的尺寸约束自相矛盾 |
| **焦距** | 建议等效 **85 mm 或更长**（中长焦） | 广角会造成近大远小的畸变，指尖（离相机近）会被放大 |
| **相机—手距离** | 建议 **0.8–1.5 m**（依焦距调整，使手在画面中占比 60–80%） | 距离过近 → 透视畸变过大 |
| **手在画面中的占比** | **60–80%**，各视角占比偏差 ≤ 5% | 尺度一致性是重建的基本约束 |
| **画面中心** | 手的几何中心居中，各视角偏差 ≤ 3% 画幅 | 腾讯官方文档建议 "subject is centered and at similar scale in each view" |
| **视角间隔** | 正交视角之间尽量接近 **90°**（斜视角 45°） | 官方建议 "front, back, and left should be 90° apart" |
| **相机高度** | 每个视角相机光轴**垂直穿过手的目标面中心** | 避免斜视造成的投影变形 |

### 2.3 光照与背景（🔒 `LIGHT = FIXED` · R1.2 定稿）

> ## 🔑 采集总原则（完整形式）
>
> ```
>        HAND   = FIXED     手保持 CANONICAL_HAND_POSE 不动
>        LIGHT  = FIXED     光照环境全程不变
>        CAMERA = MOVES     相机移动到 8 个机位
> ```
>
> **LIGHT 不跟随 CAMERA 移动。**

#### 2.3.1 `LIGHT = FIXED` 的含义

整个 8 视图采集过程中，以下**全部保持不变**：

| 项 | 要求 |
| --- | --- |
| **灯位** | 不变 |
| **光照方向** | 不变 |
| **光照强度** | 不变 |
| **色温** | 不变 |
| **柔光环境** | 不变 |

#### 2.3.2 ❌ 已废弃的方案

> 🚫 **"光源随相机同步移动"** 作为推荐方案 —— **已废弃（R1.2）**。
>
> 理由：光源跟随相机移动，意味着每个机位的光照方向都不同，这恰恰**破坏**了多视角重建所要求的光照一致性。
> 正确做法是让光照环境**本身**就是各向同性的（环绕柔光），这样相机无论移到哪个机位，手上的光照都保持一致。

#### 2.3.3 ✅ 正式推荐的光照方案

| # | 推荐 |
| --- | --- |
| 1 | **固定的环绕式柔光环境** |
| 2 | **柔光帐**（light tent） |
| 3 | **大面积漫射光** |
| 4 | 尽量减少**方向性明显的硬光** |
| 5 | 避免**强镜面高光** |
| 6 | 避免**硬阴影进入指缝** |

> **关键理解**：相机围绕手移动时，**光照环境保持不变**——因为光照环境是环绕式、各向同性的，
> 相机机位变化不会改变手上的受光状态。这才是 `LIGHT = FIXED` 与 `CAMERA = MOVES` 能共存的原因。

#### 2.3.4 多相机同步采集的定位（R1.2 澄清）

多相机同步采集**仍然可以作为优选方案**，但它的**主要价值是减少真人手随时间发生的姿态漂移**（时间维度），
**不是为了让光源跟随相机**。

> **无论单相机还是多相机**：`HAND = FIXED` / `LIGHT = FIXED` / `CAMERA VIEWPOINTS = MULTIPLE`。
> **LIGHT 不跟随 CAMERA 移动。**

#### 2.3.5 其余光照与背景要求

| 要求 | 规定 |
| --- | --- |
| **光照一致性** | 所有视角**同一光源配置、同一色温、同一强度**；官方明确要求 "consistent lighting across all reference images" |
| **光照方式** | 柔和漫射（柔光帐 / 大面积散射），**避免强方向性硬光** |
| **阴影** | **不得有硬阴影落入手部区域**，尤其不得落入指缝（会造成指缝被误判为实体） |
| **背景** | **纯色、干净、与手部明度对比明显**（建议中灰或纯白）；官方建议 "clean backgrounds (ideally transparent or solid color)" |
| **背景一致性** | 所有视角**同一背景** |
| **色温** | 统一（建议 5500 K 日光白平衡） |
| **反射** | 避免高光过曝；皮肤油光会在纹理阶段造成错误高光 |

### 2.4 手部状态

| 要求 | 规定 |
| --- | --- |
| **皮肤状态** | 无疤痕、痣、纹身、明显汗毛、污渍、反光护手霜 |
| **指甲** | 修剪整齐，长度不超过指尖；无指甲油（或全部视角一致） |
| **饰物** | **禁止**戒指、手表、手链、创可贴、绷带 |
| **👋 悬空要求（R1.1 强制）** | **手必须悬空。** 掌部、手指、指尖**一律不得**接触实体平面（桌面/拍摄台/琴键/支架）。对应母版姿态规范 §2.2.2 |
| **接触物** | **禁止**接触琴键、桌面、拍摄台、支撑面等任何实体 |
| **支撑方式** | 只允许固定**前臂末端**（悬臂式固定）。支撑物**不得进入最终手部主体区域**，且应在所有视角构图外或被后期处理掉 |
| **姿态保持** | 不得因支撑而改变 `CANONICAL_HAND_POSE` 的任何角度 |
| **掌弓保护** | 不得因任何支撑或接触压平掌心横弓与纵弓（`G-05`） |

### 3.1.1 🔒 图片总量规则（R1.2 修正 —— 此前表述有误，已更正）

> ## ⚠ 更正说明
> R1 / R1.1 中曾出现"**base64 编码后总量 ≤ 6 MB**"的表述。**这是错误的**，R1.2 已全部更正。
> 正确规则如下：

| 项 | 规则 | 性质 |
| --- | --- | --- |
| **`BASE64_ENCODED_TOTAL` ≤ 8 MB** | Base64 编码后的实际总量**必须 ≤ 8 MB** | 🔴 **腾讯官方硬约束**（必须满足） |
| **`RAW_IMAGE_TOTAL_TARGET` 约 ≤ 6 MB** | 原始图片总量**目标**约 ≤ 6 MB | 🟡 **工程侧建议值**（非官方硬上限） |

> **为什么是"约 6 MB"**：Base64 编码约产生 **30% 体积膨胀**。
> 因此若希望编码后不超过 8 MB，原始图片总量应控制在 **8 ÷ 1.3 ≈ 6.15 MB** 左右，工程上取"约 6 MB"作为目标值。
>
> **📌 写法纪律**：
> - ✅ 正确：`BASE64_ENCODED_TOTAL <= 8 MB`（硬约束）
> - ✅ 正确：`RAW_IMAGE_TOTAL_TARGET <= approximately 6 MB`（建议目标）
> - 🚫 **禁止**再写："base64 编码后总量 ≤ 6 MB"
> - 🚫 **禁止**把"约 6 MB"写成官方硬上限
>
> **📌 若使用非 Base64 传输方式**：仍以**腾讯接口实际请求限制**为权威，不得把"约 6 MB"误写成官方硬上限。

## 5. 采集原则：`HAND = FIXED / LIGHT = FIXED / CAMERA = MOVES`（R1.2 最终形式）

> ## 🔑 采集总原则（最终形式 · R1.2）
>
> ```
>        HAND   = FIXED
>        LIGHT  = FIXED
>        CAMERA = MOVES
> ```
>
> | 项 | 含义 |
> | --- | --- |
> | **`HAND = FIXED`** | 真人右手在整个 8 视图采集过程中保持**同一个 `CANONICAL_HAND_POSE`**，不得翻转、转动、重新摆放 |
> | **`CAMERA = MOVES`** | 通过改变**相机观察机位**获得 8 个视图 |
> | **`LIGHT = FIXED`** | 整个采集过程中：灯位不变、光照方向不变、光照强度不变、色温不变、柔光环境不变 |

### 5.0 ❌ 先删除一个错误前提

> **R1 版的错误前提（已作废）**：
> ~~"DORSAL（掌背）与 PALMAR（掌心）是一对相对视角，因此在真实拍摄中需要**把手翻转 180°** 后分别拍摄，
> 由此带来姿态漂移难题，必须人工裁定四种补救方案。"~~
>
> **这个前提是错的。** 之所以看起来"必须翻手"，是因为隐含假设了 **CAMERA = FIXED**（相机不动）。
> 一旦把这个隐含假设去掉，"掌心视图"就根本不需要翻手——**把相机移到手的下方去拍就可以了。**

### 5.0.1 ❌ R1.1 的另一个错误方案（R1.2 废弃）

> 🚫 **"光源随相机同步移动"** 作为推荐方案 —— **已废弃**。
>
> R1.1 曾因担心"相机移动后固定光源导致各视角光照不一致"而建议光源随动。
> **这个建议是错的**：光源跟随相机移动意味着每个机位光照方向都不同，恰恰**破坏**了光照一致性。
> 正确解法是让光照环境本身**各向同性**（固定环绕柔光 / 柔光帐 / 大面积漫射），
> 这样相机移到任何机位，手上的受光状态都不变 —— `LIGHT = FIXED` 与 `CAMERA = MOVES` 因此并不矛盾。
> 详见 §2.3。

### 5.1 正确原则

```
        ✅ 正确（R1.2 最终）              ❌ 错误（已废弃）

        HAND   = FIXED                   CAMERA = FIXED
        LIGHT  = FIXED                   HAND   = FLIPPED
        CAMERA = MOVES                   LIGHT  = FOLLOWS CAMERA  ← R1.2 废弃

        手保持 CANONICAL_HAND_POSE       手被翻转 180° 重拍
        光照环境全程不变                  → 关节角度漂移
        相机围绕手移动到 8 个机位          → 张开角不一致
        → 姿态 + 光照均天然一致            → 掌弓被压平
                                          → 各机位光照方向各异
```

**DORSAL 与 PALMAR 因此不再是"一对需要翻手才能凑齐的矛盾视角"，而只是同一只不动的手从 +Y 侧与 −Y 侧各拍一张。**
**且因为光照是固定环绕柔光，两个机位下的手部受光状态一致。**

### 5.2 首选采集路线（A–G）

| 步骤 | 规定 |
| --- | --- |
| **A. 固定前臂末端，手悬空** | 以悬臂方式固定**前臂末端**，使手在自重下**悬空**保持 `CANONICAL_HAND_POSE`。不得让掌部、手指、指尖接触任何实体平面。 |
| **B. 支撑物不得进入手部主体区域** | 支撑/夹持装置**只作用于前臂末端**，**不得进入最终手部主体区域**（腕以远部分）。若无法完全避开构图，须在后期处理中去除，并在 `CONSISTENCY_REPORT.md` 中登记。 |
| **C. 相机围绕固定手移动** | 相机（或相机阵列）围绕这只不动的手移动到 8 个机位：DORSAL / PALMAR / RADIAL / ULNAR / DISTAL / PROXIMAL / 两个斜视图。 |
| **D. 获取全部八视图** | 一次固定，拍齐 8 个视角。 |
| **E. 同一只右手、同一姿态** | 全程**同一只右手**、**同一个 `CANONICAL_HAND_POSE`**。手在整个过程中不得被翻转、转动或重新摆放。 |
| **F. 多相机同步采集优先** | **若条件允许，多相机同步采集优先**（rig / 相机阵列同时触发）。<br>📌 **R1.2 澄清**：其主要价值是**减少真人手随时间发生的姿态漂移**（时间维度），**不是为了让光源跟随相机**。光照仍须遵循 `LIGHT = FIXED`。 |
| **G. 单相机快速环绕为可行方案** | **单相机快速环绕采集**作为可行方案（同一相机依次移动到各机位快速拍摄）。须在前后各复拍一次 DORSAL 作为漂移校验基准（见 §5.4）。 |

### 5.3 与相机移动配套的两条硬约束（🔒 R1.2 修正）

| # | 约束 | 理由 |
| --- | --- | --- |
| **MV-01** | **相机—手距离在每个机位保持一致**（相机在以手为中心的球面上移动） | 距离变化会改变透视比例，破坏多视角重建的尺寸约束。相机是"绕球面移动"，不是"前后推拉"。 |
| **MV-02**（R1.2 重写） | **`LIGHT = FIXED`：光照环境全程不变** —— 灯位、方向、强度、色温、柔光环境均不变。<br>实现方式：**固定环绕式柔光环境 / 柔光帐 / 大面积漫射光**，使光照本身各向同性，相机移到任何机位手部受光状态都一致。 | 相机移动后若各视角光照不一致，会破坏多视角重建的一致性假设。<br>🚫 **不得**采用"光源随相机同步移动"（R1.2 废弃，见 §5.0.1）。 |

> ⚠ **MV-02 是本采集路线的关键风险点（对应风险登记册 `RK-14`）**。
> R1.1 曾误将"光源随动"作为解法；R1.2 更正为：**让光照环境固定且各向同性**，从环境本身消除机位差异。
> 多相机同步采集仍可作为优选（减少时间漂移），但**不改变 `LIGHT = FIXED` 原则**。

### 5.4 漂移校验（单相机方案必做）

采用 §5.2 G（单相机快速环绕）时，**必须**执行：
1. 环绕拍摄**前**拍一张 `DORSAL_PRE`；
2. 环绕拍摄**后**再拍一张 `DORSAL_POST`；
3. 比对 `DORSAL_PRE` 与 `DORSAL_POST` 的指长比、张开角、掌宽比；
4. 偏差超限 → 判定采集失败，重采。

> 采用 §5.2 F（多相机同步）时，因不存在时间维度漂移，此项可简化为一次 `DORSAL` 基准留档。
